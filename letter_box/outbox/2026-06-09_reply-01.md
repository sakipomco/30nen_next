## R-01 → 採用（今回対応）
- 判断: 採用
- 理由: 書き手が20名以上いる前提で、ログインさえあれば他人の記事を直接のServer Action送信で更新・削除できる状態は実害が大きい。UIのリンク非表示だけでは防げないという根拠も妥当。
- 対応: 更新・削除の直前に、対象記事の `authorId` がログイン中ユーザー本人、またはユーザーが `admin` であることをサーバー側で確認する。管理一覧 `/admin` も投稿者には本人の記事のみ表示する。編集ページも操作不可なら弾く。
- 状態: **対応済み（commit b42184a）**。`db/articles.ts` に `canManageArticle()` を追加し、更新・削除Action・編集ページ・一覧で適用。

## R-02 → 採用（今回対応）
- 判断: 採用
- 理由: `dangerouslySetInnerHTML` で本文HTMLを無検査表示し、保存側も `content` を素通ししている。投稿者アカウント経由で閲覧者にXSSが成立しうるという指摘どおり。
- 対応: HTMLサニタイズを導入し、許可タグ・属性をホワイトリスト化、`script`/`style`/`on*`イベント属性/`javascript:` URL を除去する。保存時または表示直前のいずれかに適用。
- 状態: **対応済み（commit b42184a）**。`sanitize-html` を導入し `lib/sanitize.ts` を新設。保存時（作成・更新Action）＋表示時（記事詳細）の両方で適用。`script`/`on*`/`javascript:` の除去をテストで確認。

## R-03 → 採用（今回対応）
- 判断: 採用
- 理由: `next/font/google` の Geist / Geist Mono は create-next-app の名残で、実表示は `<head>` のGoogle Fonts CDN（明朝系）を使用している。未使用フォントのためにビルド時の外部取得へ依存し、ネットワーク制限下でデプロイ不能になるのは避けたい。
- 対応: `src/app/layout.tsx` から `next/font/google` 利用を撤去し、`globals.css` の `--font-geist-*` 前提も整理する。表示は既存のCDNフォントに寄せる。
- 状態: **対応済み（commit b42184a）**。Geist撤去・`--font-sans/mono` をOS標準スタックに変更。`npm run build` の成功を確認。
