## R-01 〔重要度: 高〕 投稿者が他人の記事を編集・削除できる可能性がある
- 該当: `src/app/actions/articles.ts:123`
- 該当: `src/app/actions/articles.ts:147`
- 該当: `src/app/admin/page.tsx:17`
- 指摘: 記事の更新・削除処理はログイン確認をしているが、対象記事の `authorId` がログイン中ユーザー本人か、またはログイン中ユーザーが管理者かを確認していない。管理画面の一覧も `listArticles()` で全記事を表示している。
- 提案: `admin` は全記事を操作可能、`author` は `article.authorId === user.id` の記事だけ操作可能にする。管理一覧も投稿者には本人の記事だけ表示する。編集ページでも、対象記事が操作可能でなければ `notFound()` または `/admin` への誘導にする。
- 根拠: UI上のリンク非表示だけでは Server Action への直接送信を防げないため、更新・削除の直前にサーバー側で所有者チェックが必要。

## R-02 〔重要度: 高〕 記事本文HTMLがサニタイズされず公開表示されている
- 該当: `src/app/(public)/posts/[slug]/page.tsx:108`
- 該当: `src/app/actions/articles.ts:80`
- 該当: `src/app/admin/rich-editor.tsx:160`
- 指摘: 記事詳細で `dangerouslySetInnerHTML` により本文HTMLを表示しているが、保存側ではフォームから来た `content` をそのまま保存している。TipTapの画面上の制限はあるが、Server Actionには改ざんしたHTMLを直接送信できる。
- 提案: 保存時、または表示直前にHTMLサニタイズを入れる。許可タグ・属性を明示し、`script`、`style`、イベント属性 `on*`、`javascript:` URL を除去する。
- 根拠: 投稿者アカウントを持つ利用者、または侵害された投稿者アカウントから、公開ページ閲覧者に対するXSSが成立する可能性がある。

## R-03 〔重要度: 高〕 本番ビルドがGoogle Fonts取得に依存して失敗する
- 該当: `src/app/layout.tsx:2`
- 該当: `src/app/layout.tsx:5`
- 指摘: `npm run build` 実行時、`next/font/google` が `Geist` / `Geist Mono` をGoogle Fontsから取得できずビルドが失敗した。
- 提案: `next/font/google` の利用をやめ、既に `<head>` で読み込んでいるGoogle Fonts CDNに寄せるか、必要フォントをセルフホストする。あわせて `globals.css` の `--font-geist-*` 前提も整理する。
- 根拠: CIや本番サーバーで外部ネットワーク取得が不安定・制限されると、アプリコードに問題がなくてもデプロイ不能になる。

## R-04 〔重要度: 中〕 公開ナビに未実装ページへのリンクが出ている

## R-05 〔重要度: 中〕 存在しないページ番号で「記事がありません」と表示される

- 該当: `src/app/(public)/page.tsx:62`
