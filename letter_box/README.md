# letter_box — レビュー連絡用フォルダ

このフォルダは、**このプロジェクトを別のエージェント（レビュー担当）が客観的に評価し、
その指摘を担当エージェント（Claude Code）に渡すための「連絡ポスト」**です。
人どうしの郵便受けのように、決まった場所にファイルを置き合うことでやり取りします。

---

## フォルダの構成

```
letter_box/
├── README.md      ← このファイル（運用ルール）
├── inbox/         ← レビュー担当が「指摘」を置く場所
└── outbox/        ← Claude Code が「採用判断の返信」を置く場所
```

- **inbox**（インボックス＝受信箱）… レビュー担当エージェントが、気づいた指摘を `.md` で置く。
- **outbox**（アウトボックス＝送信箱）… Claude Code が、オーナー（SAKI）と相談したうえで
  「採用する／しない＋理由」をまとめた返信を `.md` で置く。

---

## ファイル名のルール

日付と連番をつけて、時系列が分かるようにします。

- レビュー指摘：`inbox/YYYY-MM-DD_review-01.md`（例：`inbox/2026-06-09_review-01.md`）
- 採用判断の返信：`outbox/YYYY-MM-DD_reply-01.md`（例：`outbox/2026-06-09_reply-01.md`）

返信ファイル名は、対応する指摘ファイルと同じ日付・連番にそろえると対応関係が分かりやすいです。

---

## レビュー担当エージェントへのお願い（指摘の書き方）

`inbox/` に置く指摘ファイルは、次のテンプレートに沿って書いてください。
**指摘ごとに「ID・重要度・該当ファイル・内容・提案」をそろえる**と、採否の判断がしやすくなります。

```markdown
# レビュー指摘 YYYY-MM-DD（第N回）

レビュー担当: （エージェント名やモデル名など）
対象: （ブランチ名・コミットハッシュなど、何を見たか）

## R-01 〔重要度: 高 / 中 / 低〕 一言タイトル
- 該当: path/to/file.tsx:42
- 指摘: 何が問題か（事実ベースで）
- 提案: どう直すとよいか
- 根拠: なぜそう言えるか（あれば）

## R-02 〔重要度: 中〕 ...
- 該当: ...
- 指摘: ...
- 提案: ...
```

- 指摘には `R-01`, `R-02` … と**通し番号（ID）**をつけてください。返信でこのIDを使います。
- 重要度は **高 / 中 / 低** の3段階。
- 推測で断定せず、「事実」と「提案・意見」は分けて書いてください。

---

## 返信のルール（Claude Code 側）

Claude Code は、オーナー（SAKI）と議論したうえで、指摘1件ずつに対して
**採用 / 一部採用 / 見送り / 保留** のいずれかと、その理由を返します。
レビュー担当の指摘に**すべて従う必要はありません**。判断の主体はオーナーです。

返信テンプレート：

```markdown
# 採用判断の返信 YYYY-MM-DD（第N回）

対応する指摘: inbox/YYYY-MM-DD_review-01.md

## R-01 → 採用
- 判断: 採用
- 理由: ...
- 対応: 実際に直した内容 / コミットハッシュなど

## R-02 → 見送り
- 判断: 見送り
- 理由: ...
```

判断の区分：
- **採用** … その通り直す。
- **一部採用** … 一部だけ取り入れる（どこを変えるか明記）。
- **見送り** … 今回は直さない（理由を明記）。
- **保留** … 判断を後回し（理由・いつ決めるか）。
