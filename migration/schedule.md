# 移行スケジュール案（v1）

作成日: 2026-06-09 ／ 対象: 30nen.com を WordPress から新システムへ移行

> このファイルは**たたき台（案）**です。SAKIさんと相談しながら直していきます。
> 専門用語にはそのつど短い説明を添えています。

## 0. 前提（SAKIさんの希望）

| 項目 | 決めたこと |
|------|-----------|
| 切替の目標時期 | **7月下旬**（可能であれば） |
| 書き手の乗り換え方 | **並行期間を設ける**（一定期間は新旧どちらでも投稿できる） |
| WordPressの投稿 | **止めない**（毎日投稿される日記サイトのため）。ただし作業はなるべく単純に |
| 多言語サポート | マニュアルを**スペイン語＋日本語**で用意／**質問の窓口**も設けたい |

> 用語メモ
> - **移行（いこう）** … 古いシステム（WordPress）から新システムへ、記事・画像・運用を引っ越すこと。
> - **切替（きりかえ）** … 公開アドレス `30nen.com` を、新システムの方に向ける日。これ以降、訪問者が見るのは新サイト。
> - **並行期間** … 新旧の両方が動いている期間。書き手が少しずつ新システムに慣れるための助走期間。

## 1. いちばん大事な考え方（なぜこの進め方か）

「毎日投稿があるサイトを、投稿を止めずに引っ越す」と、ふつうは**“どっちが本物の最新データか”がこんがらがり**ます。
そこで、こう整理します。

> ### ★ 並行期間中のルール（提案）
> - **本番の投稿は、切替日まで今までどおり WordPress に**（＝本物の記事は常に WordPress に集まる）。
> - **新システムは、並行期間中は「練習・お試し」**。書き手はログインして投稿画面に慣れる／お試し投稿をする。
> - お試し投稿は切替後に消してもOK（本物ではないため）。
> - **切替日に、WordPress の全記事を新システムへ一括で移す**（出どころが1か所なので迷子が出ない）。
> - 切替後は、**全員 新システムだけに投稿**する。

この方法のいいところ:
- WordPress の投稿を**1日も止めずに**済む（SAKIさんの希望どおり）。
- 移すデータの出どころが**常に WordPress の1か所**なので、手順がいちばん単純。
- 書き手は本番前に新画面を**安心して練習**できる。

気をつける点:
- 並行期間中に新システムへ書いた「お試し記事」は本物扱いしない（切替後に必要なら本人が投稿し直す）。この点だけ書き手にハッキリ伝える。

## 2. 記事データの移し方（技術の段取り・Claude Code 担当）

移行スクリプト（記事を自動で移す小さなプログラム）は、**何度実行しても安全**な作りにします。

> 用語メモ
> - **スクリプト** … 決まった作業を自動でやってくれる小さなプログラム。
> - **冪等（べきとう／idempotent）** … 同じ処理を何回流しても結果が壊れない性質。今回は「すでに移した記事は飛ばす」作りにする。
> - **wp_id** … WordPress 側の記事の通し番号。新システムの各記事にこの番号を控えておき、「もう移したか」を判定する保険に使う（DB設計で確保済み）。

### 流れ
1. **リハーサル移行（自分のパソコン上で）**: 本番 WordPress から全記事を**読み取りだけ**で取り出し、新システムへ試しに流し込む。件数・文字化け・画像リンク切れ・カテゴリ対応・著者対応を点検。← 早めにやって想定外を洗い出す。
2. **本移行①（一括）**: 切替の少し前に、サーバー上の新システムへ全記事を一括投入。
3. **本移行②（差分／さぶん）**: 切替直前に、①以降に WordPress に増えた分だけ**同じスクリプトを再実行**して追加。`wp_id` のおかげで重複は自動で飛ばす。

> 用語メモ
> - **差分移行** … 「前回移したあと新しく増えた分だけ」を追って移すこと。スクリプトは同じものを再実行するだけ。

### 移行で自動処理すること
- 本文中の**画像URLの書き換え**（WordPress の住所 → 新サイトの住所）。
- 画像ファイル本体の**ダウンロード＆配置**（`wp-content/uploads` → 新サイトの保存場所）。
- 記事の**カテゴリー（連載）対応**・**著者（書き手）対応**づけ。
- 公開日時・本文HTMLの保持。

### ★ 移行の範囲（SAKIさんと確定）

| 項目 | 決めたこと |
|------|-----------|
| 読者コメント | **移行しない**（残さない）。新システムは「お便りフォーム」で代替。 |
| 下書き | **移行しない**（公開記事 約7,790件のみ移す）。 |
| 記事のアドレス（slug） | **現行と同じに保つ** ✅（検索エンジン・既存リンクが切れないように）。 |

> 用語メモ
> - **slug（スラッグ）** … 記事ごとのアドレスの末尾部分（例: `30nen.com/`**`koharu-biyori`**）。これを現行と同じにすれば、昔のリンクや検索結果をクリックしても新サイトの同じ記事にたどり着く。

### ★ 残った確認事項：著者の対応表

現行 WordPress は記事ごとに「書いた人＝**著者番号（数字）**」で記録している。新システムは20名のアカウントを作り直すので、「**WP著者番号 ↔ 新システムの誰か**」を結びつける一覧（対応表）が必要。これが無いと移行記事の「書いた人」が正しくひもづかない。

進め方:
1. Claude Code が現行 WordPress から著者一覧（**番号・表示名・メール**）を**読み取りだけ**で取得。
2. SAKIさんが「この番号＝新システムのこの人」を埋める。
3. 移行スクリプトがこの表を使って記事を正しい書き手にひもづける（誰がどの連載担当かも合わせて確定）。

## 3. 全体スケジュール（週ごと・目安）

> 切替の目標が**7月下旬**なので、今日（6/9）から約7週間の組み立てです。
> 3つの作業が**同時並行**で進みます: **A サイト仕上げ** / **B 記事移行** / **C 書き手の乗り換え**。

| 週 | 期間（目安） | A. サイト仕上げ（SAKI×Claude） | B. 記事移行（Claude Code） | C. 書き手の乗り換え |
|----|-------------|------------------------------|--------------------------|--------------------|
| W0 | 6/9〜6/15 | 残りページ実装（連載別一覧・著者・about・月別アーカイブ） | **リハーサル移行**で問題点を洗い出し | 書き手20名の名簿・担当連載・メアドを確定 |
| W1 | 6/16〜6/22 | 残りページ仕上げ・微調整 | リハーサルの不具合修正（画像・文字化け等） | **マニュアル作成**（日本語＋スペイン語）／操作動画の検討 |
| W2 | 6/23〜6/29 | **Xサーバーへデプロイ**（テスト用アドレスで公開） | サーバー上で再リハーサル | 質問窓口を準備（後述） |
| W3 | 6/30〜7/6 | 本番アカウント20名を作成・担当連載ひもづけ | — | **アナウンス①（予告）**＋マニュアル配布。**並行期間スタート**（練習OK） |
| W4 | 7/7〜7/13 | 動作確認・調整（書き手のつまずき対応） | — | 書き手が各自ログイン→お試し投稿。窓口で質問対応 |
| W5 | 7/14〜7/20 | 最終チェック | **本移行①（全記事の一括投入）** | **アナウンス②（リマインド）**「○/○に切替」 |
| W6 | 7/21〜7/27 | 切替後の見守り | **本移行②（差分）→ 切替（ドメイン向け替え）** | 切替日サポート／**全員 新システムへ** |

> 用語メモ
> - **デプロイ** … 作ったサイトをサーバーに置いて、インターネットからアクセスできる状態にすること。
> - **テスト用アドレス** … `30nen.com` に向ける前の、確認用の仮アドレス。書き手の練習にも使う。
> - **ドメイン向け替え** … `30nen.com` の行き先を WordPress から新サイトに切り替える設定。

### ⚠ 正直なところ（スケジュールの見立て）
7月下旬は**やや強気な目標**です。サイトの残り作業（連載別ページ・著者ページ・about・月別アーカイブ・デプロイ・テスト）が予定どおり進むことが前提になります。
そこで、**W2終わり（6/29ごろ）に「行ける／延ばす」の判断ポイント**を置くことを提案します。ここで間に合いそうになければ、切替を1〜2週間うしろにずらす――と決めておけば、慌てず安全に進められます。

## 4. 書き手の乗り換えスキーム（20名・海外/非日本語話者を含む）

### 4-1. アナウンス（お知らせ）のタイミングと中身
2回に分けて、**日本語＋スペイン語**で出します。

- **アナウンス①（予告・W3 / 6月末〜7月頭）**
  - 「新しい投稿システムに移ります」「○月○日ごろ切替予定」「それまでは今までどおり WordPress に投稿してOK」
  - 新システムのテスト用アドレス・ログイン方法・マニュアルのありか
  - 「並行期間中の新システムは練習用。本物の投稿は切替まで WordPress に」
- **アナウンス②（リマインド・W5 / 7月中旬）**
  - 「○月○日に正式切替。それまでに一度ログインして練習を」
  - 切替当日の流れ・困ったときの窓口

### 4-2. マニュアル（スペイン語＋日本語）
- 内容: ログイン → 記事を書く（タイトル・本文・写真）→ 下書き保存／投稿 の3ステップだけ（投稿画面はもともとシンプル設計）。
- 形式: 画像付きの手順書（PDF or Webページ）。**操作動画**も用意できると、言葉が違っても見て真似でき効果的（要検討）。

### 4-3. 質問対応の窓口
- 海外・時差を考え、**書き込み式の窓口**（例: 専用メール、チャットグループ、または新サイト内のお便りフォーム流用）を1つ決めて周知。
- 並行期間〜切替直後を**重点サポート期間**として、返信担当を決めておく。

### 4-4. アカウントとパスワード
- 管理画面から20名分を作成（担当連載をひもづけ＝投稿時に連載が自動セットされ「未分類」を防ぐ仕組みは実装済み）。
- 初回パスワードの**安全な配り方**を決める（次回相談。なるべく簡単で安全な方法を提案します）。

## 5. 切替（カットオーバー）当日の段取り

1. WordPress 側の最終投稿を確認（前夜〜当日朝で区切る）。
2. **本移行②（差分）**を実行＝前回移行後に増えた WordPress 記事を追加。
3. 新サイトで件数・最新記事・画像表示を点検。
4. **ドメイン向け替え**（`30nen.com` → 新サイト）。
5. 数件、実際に表示・投稿して最終確認。
6. 書き手に「切替完了。今後は新システムへ」と連絡。

### 切替後
- WordPress は**すぐ消さず数週間 温存**（読み取りのみ）。漏れ・不具合がないか見守る。
- 問題なければ WordPress を停止（フェーズ5完了）。
