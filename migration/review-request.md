## 1. プロジェクト概要

- **対象サイト**: 30nen.com（「三十年商店」）。**20名以上の書き手が毎日投稿する日記サイト**。
- **記事数**: 公開記事 **約7,790件**（1年で約+7,300件ペースで増加中）。
- **現状**: WordPress（レンタルサーバー＝Xサーバー上）で本番稼働中。
- **やること**: WordPress → **自前のNext.jsシステム**へ全記事を移行し、公開アドレス `30nen.com` を新システムへ切り替える。
- **重要な制約**: 毎日投稿があるため、移行作業中も **WordPressは止めず並行稼働**。現行WordPressは移行完了まで**読み取りのみ**（触らない）。
- **ゴール**: 運用の手間削減／ITに不慣れな20名超が使える**シンプルな投稿画面**／月額SaaS費ゼロ（サーバー代のみ）／既存記事を**全件移行**。
- **体制**: オーナー（IT初心者寄り・以下「オーナー」）＋ AIコーディングエージェント（Claude Code）の2者。専任エンジニアはいない。

### 書き手の特性（重要）
- 20名以上。**半数近くが海外在住・非日本語話者（スペイン語話者を含む）**。ITリテラシーは高くない。
- 投稿頻度は各人1日数回程度（同時書き込みは軽い）。

## 3. 移行方針の要点（すでに決めたこと）

### 並行期間のルール
- 本物の投稿は**切替日までWordPressに**集める（出どころを1か所に）。
- 新システムは並行期間中は**練習用（お試し）**。書き手はログインして投稿画面に慣れる。お試し投稿は切替後に消えてOK。
- **切替日に、WordPressの全記事を新システムへ一括で移す**。以後は全員 新システムだけに投稿。

### 移行の範囲（確定）
| 項目 | 決めたこと |
|------|-----------|
| 読者コメント | 移行しない（新システムは「お便りフォーム」で代替） |
| 下書き | 移行しない（公開記事 約7,790件のみ） |
| 記事のアドレス(slug) | **現行と同じに保つ**（旧リンク・検索結果が切れないように） |

### 移行スクリプトの設計
- **冪等（何度流しても安全）**: すでに移した記事は `wp_id` で判定して飛ばす。
- 自動処理: 本文中の画像URL書き換え／画像本体のダウンロード＆配置／著者・連載のひもづけ／公開日時・本文HTMLの保持。
- WordPressは**読み取りのみ**、書き込み先は新DBのみ。
- **本移行①（一括）**＝切替少し前に全件投入 → **本移行②（差分）**＝切替直前に増えた分だけ追加。

### 残課題
- **著者対応表**: 現行は記事ごとに「著者番号（数字）」で記録。新20アカウントとの対応表が必要。退会済み著者の扱いも要検討。

## 6. 評価してほしいこと（ここに答えてください）

1. **達成可能性**: 今日6/16から「7月下旬切替」は現実的か？ 無理がある場合、ボトルネックはどこで、どれくらい後ろ倒しが妥当か。
2. **クリティカルパス**: このスケジュールで最も危ういタスク（遅れると全体が崩れる箇所）はどれか。
3. **抜け・見落とし**: スケジュールに**入っていないが必要な作業**はないか。特に次の観点で点検してほしい:
   - デプロイ／本番環境（初デプロイなのにW+1でテスト公開できるか・PM2/Nginx・SSL証明書）
   - SEO・リンク維持（slug以外に、301リダイレクト・sitemap.xml・robots・OGP・旧パーマリンク構造との一致は足りているか）
   - データ整合（本番DBの初期化手順・著者対応表づくりの所要時間・画像の総容量と転送時間）
   - **バックアップとロールバック**（切替に失敗したらWordPressへ戻せるか・戻し方）
   - DNS切替の実務（TTL・反映待ち・切替の時間帯）
   - 公開ページの未実装分が間に合うか（記事詳細・連載別・著者・アーカイブ）
   - 並行期間ルールの穴（お試し投稿と本番投稿の取り違え・切替直前にWordPressへ来た投稿の取りこぼし）
   - 書き手サポートの十分性（多言語マニュアル・質問窓口・パスワード配布・つまずき対応の人手）
4. **リスクと対策**: 上記で見つかった懸念に対し、現実的な緩和策・代替案を提案してほしい。
5. **総合判定**: 「このまま進める／一部修正して進める／時期を見直す」のどれを推すか、理由とともに。
